# Модульная архитектура

Cattr построен на основе модулей. Это значит, что каждый компонент системы независим и расширяем. Модули могут расширять как ядро Cattr, так и сторонние модули от других разработчиков (см. Перехват инициализации модулей).
Модульная архитектура позволяет сделать ядро Cattr независимым, что позволяет его без особых проблем и конфликтов. Любой модуль может быть отключен от ядра без вреда для основного функционала приложения.

Модель рендера Cattr позволяет разработчику управлять всеми частями приложения. Так, отдельными и независимыми сущностями представлены следующие компоненты:

1. Навигационная панель
2. Основное окно взаимодействия с пользователем
3. Пользовательские настройки
4. Системные настройки (изначально доступны только root-пользователям)

> Для взаимодействия с этими элементами в Cattr присутствуют все необходимые интерфейсы. Работа с этими интерфейсами осуществляется через контекст создаваемого модуля.

# Разработка модуля

Для того, чтобы начать взаимодействовать с ядром Cattr, необходимо создать модуль.
Для этого, в каталоге vendor_modules необходимо создать каталог с названием вендора модуля, затем, внутри созданного каталога создать каталог с названием создаваемого модуля.

```text
Созданная структура каталогов в итоге должна иметь следующий вид:
resources
└──frontend
    └──vendor_modules
        └── MyCompanyName/
            ├── MyModuleName1/
            │   └── module.init.js
            ├── MyModuleName2/
            │   └── module.init.js
            ├── MyModuleName3/
            │   └── module.init.js
            └── ...

```

> Название модуля получается по следующему шаблону: __VendorName_ModuleName__. Это сделано для того, чтобы уменьшить количество конфликтующих по названию модулей.

## Инициализация модуля

Основой модуля является файл точки входа. Он отвечает за инициализацию и базовую настройку модуля.
В созданном каталоге модуля необходимо создать файл module.init.js. Именно он будет загружаться менеджером модулей при загрузке приложения.

module.init.js **обязательно** должен экспортировать две сущности: ___функцию init___ и ___константу ModuleConfig___, подробнее об этом см. ниже

Шаблон файла module.init.js

```javascript
import i18n from '@/i18n';
/**
 * Конфигурация модуля
 *
 * @type {{routerPrefix: string, enabled: boolean, initOrder: number, moduleName: string}}
 */
export const ModuleConfig = {
    // Этот модуль должен быть включен или нет (влияет только на локальный экземпляр модуля)
    enabled: true,
    // Префикс роутера по умолчанию. Обратите внимание: этот параметр будет игнорироваться в context.addRoutes().
    // Сущности Grid и Crud будут автоматически иметь этот префикс
    routerPrefix: 'settings',
    // Порядок загрузки для этого модуля.
    // Обратите внимание: это влияет только на порядок выполнения функции init().
    // module.init.js будет загружаться в алфавитном порядке названий модулей
    loadOrder: 11,
    // Имя модуля Node
    moduleName: 'AmazingCat_JiraIntegration',
};

/**
 * Функция инициализации модуля по умолчанию, будет выполнена при инициализации модуля.
 * Context — текущий экземпляр модуля
 * Router — текущее состояние Vue Router
 *
 * Эта функция ДОЛЖНА ВСЕГДА возвращать контекст
 *
 * @param context: Module
 * @param router: Router
 * @returns {Module}
 */
export function init(context, router) {
    const requireSection = require.context('.', true, /^(?!.*(service|module)).*\.js$/);
    const sections = requireSection
        .keys()
        .map(fn => requireSection(fn).default)
        .map(section => {
            if (typeof section === 'function') { 
                return section(context, router);
            }
            return section;
        });

    sections.forEach(section => {
        if (section.hasOwnProperty('scope') && section.scope === 'company') {
            context.addCompanySection(section);
        } else {
            context.addSettingsSection(section);
        }
    });
    //moduleLoader инициализирует модуль вызывая его функцию init 
    context.addField('company', 'general', {
        label: 'settings.jira.label',
        key: 'jira_enabled',
        group: 'integrations',
        //ItemView добовляет этот компонент, в шаблоне они все перебираются и отрисовываются
        render(h, data) {
            if (typeof data.currentValue === 'object') {
                'jira_enabled' in data.companyData
                    ? data.inputHandler(data.companyData.jira_enabled)
                    : (data.currentValue = '0');

                this.inputHandler(data.currentValue);
            }
            return h(
                'at-select',
                {
                    props: {
                        value: data.currentValue.toString(),
                    },
                    class: {
                        'with-margin': true,
                    },
                    on: {
                        'on-change': value => {
                            data.inputHandler(value);
                        },
                    },
                },
                [
                    h('at-option', {
                        props: {
                            value: '0',
                            label: i18n.t('control.disable'),
                        },
                    }),
                    h('at-option', {
                        props: {
                            value: '1',
                            label: i18n.t('control.enable'),
                        },
                    }),
                ],
            );
        },
    });
    //Добавление данных для локализации
    context.addLocalizationData({
        en: require('./locales/en'),
        ru: require('./locales/ru'),
    });

    return context;
}
```

### ModuleConfig

Константа ModuleConfig - экспортируемый объект, состоящий из 4 свойств.

1. __enabled__ - свойство, отвечающее за то, будет ли модуль включен по умолчанию или нет (может перезаписано администратором в файле app/etc/modules.config.json). Данное свойство имеет эффект тогда и только тогда, когда модуль был установлен локально, а не как node-пакет.
2. __routerPrefix__ - свойство, отвечающее за базовый префикс роутов для GRID и CRUD страниц. Обратите внимание, что данное свойство не влияет на добавляемые роуты через метод addRoutes экземпляра context.
3. __initOrder__ - свойство, управляемое порядком инициализации модулей (все модули инициализируются в порядке очереди, чем меньше число, тем первее будет инициализирован модуль). По-умолчанию - 0. Обратите внимание, что данное свойство влияет только на порядок инициализации модуля, файл точки входа модуля будет загружен в алфавитном порядке.
4. __moduleName__ - свойство, устанавливающее имя модуля. Влияет только на модули, установленные через пакетный менеджер.

### Функция инициализации "init"

Функция init ___всегда___ должна экспортироваться из файла точки входа модуля. Она описывает поведение модуля. В качестве аргументов функция принимает два параметра - __context__ и __router__.

?> Функция init всегда должна возвращать передаваемый в нее context!

__context__ является основным интерфейсом взаимодействия с API Cattr. Любые взаимодействия с ядром Cattr должны производиться только через контекст.
Простыми словами, context является сущностью, которая и представляет создаваемый модуль. Более подробно о методах взаимодействия с ядром через контекст смотрите в разделе Context.

__router__ представляет из себя экземпляр Vue Router'а. Если по каким-то причинам необходимо добавить маршруты в обход ограничений возможностей модульной архитектуры, можно воспользоваться сущностью router.

!> Cattr построен на фреймворке VueJS. Хоть архитектура приложения и не ограничивает разработчика в каких-либо аспектах разработки, крайне не рекомендуется взаимодействовать с API VueJS напрямую в обход ядра Cattr (взаимодействие с Vue Router вне контекста модуля обходит любые ограничения ядра), так как это может повлечь за собой непредвиденное поведение приложения в будущем и сильно усложняет поддержку модуля со стороны других команд или разработчиков.

!> ___Наличие возможности взаимодействия с Vue Router напрямую внутри функции инициализации модуля не является гарантией стабильности работы приложения после произведенных с роутером операций.___
