# Хранение файлов: локальный диск или S3

Cattr хранит три вида файлов. Каждый из них лежит либо на локальном диске (`storage/app`, volume / PVC), либо в S3-совместимом бакете (AWS S3, MinIO и т. п.).

| Файлы | Диск | Переменная | Локально | Префикс ключа в S3 |
|---|---|---|---|---|
| Скриншоты и миниатюры | диск по умолчанию | `FILESYSTEM_DISK=local\|s3` | `storage/app/screenshots/` | `<AWS_ROOT>/screenshots/` |
| Вложения задач | `attachments` | `ATTACHMENTS_DISK=local\|s3` | `storage/app/attachments/` | `<AWS_ROOT>/attachments/` |
| Сформированные отчёты | `reports` | `REPORTS_DISK=local\|s3` | `storage/app/public/reports/` (отдаются по `/storage`) | `<AWS_ROOT>/reports/` |

Временные файлы (загружаемые скриншоты, архивы офлайн-синхронизации) всегда остаются на локальном диске.

## Настройки S3

| Переменная | Назначение |
|---|---|
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | ключи доступа |
| `AWS_DEFAULT_REGION` | регион, по умолчанию `us-east-1` (для MinIO подойдёт любой) |
| `AWS_BUCKET` | бакет, общий для всех дисков на S3 |
| `AWS_ROOT` | необязательный префикс ключей внутри бакета |
| `AWS_ENDPOINT` | адрес сервиса, если это не AWS, например `https://minio.example.com`; подписанные ссылки подписываются на этот хост (см. ниже) |
| `AWS_USE_PATH_STYLE_ENDPOINT` | `true` для MinIO и большинства self-hosted сервисов |
| `AWS_TEMPORARY_URL` | необязательно; заменяет схему, хост и порт подписанных ссылок, только для CDN / прокси, который сохраняет подписанный хост (см. ниже) |

Бакет остаётся приватным: браузер получает только подписанные ссылки.

### Адрес для подписанных ссылок

Подписанная ссылка подписывается AWS Signature V4 на хост из `AWS_ENDPOINT`, и `Host` входит в подпись (`X-Amz-SignedHeaders=host`). Хранилище отклоняет ссылку, пришедшую с другим `Host`.

- **Рекомендуется:** указать в `AWS_ENDPOINT` адрес, по которому хранилище доступно под одним и тем же именем и из подов Cattr, и из браузера, например публичный адрес MinIO (`https://minio.example.com`) с `AWS_USE_PATH_STYLE_ENDPOINT=true`, а `AWS_TEMPORARY_URL` оставить пустым.
- `AWS_TEMPORARY_URL` ничего не переподписывает: Laravel подписывает ссылку на `AWS_ENDPOINT` и потом заменяет только схему, хост и порт (путь из `AWS_TEMPORARY_URL` игнорируется). Используйте его только для CDN или обратного прокси, который передаёт запросы в хранилище с `Host` из `AWS_ENDPOINT`. Внутренний адрес вроде `http://minio:9000` вместе с ingress, который передаёт публичный `Host` браузера, даёт `SignatureDoesNotMatch`.

## Как браузер получает файлы

- **Скриншоты.** `time-intervals/list` и `time-intervals/show` возвращают `screenshot_url` и `thumbnail_url`, которые действуют **10 минут**. На локальном диске это относительные адреса `GET /api/time-intervals/{id}/screenshot|thumb` с временной подписью (bearer-токен не нужен, неверная или просроченная подпись даёт 403). Эти два маршрута ограничены по IP: `SCREENSHOTS_RATE_LIMIT` запросов в минуту, по умолчанию 600, чего хватает на полный день таймлайна со скриншотами раз в минуту. Увеличьте значение, если много пользователей выходят с одного IP (офисный NAT, прокси без передачи адреса клиента). На S3 это подписанные ссылки на объекты. `GET /api/time-intervals/{id}/screenshot-urls` (с авторизацией, та же проверка доступа, что и для просмотра интервала) выдаёт свежие ссылки. Фронтенд вызывает его для отчётов, в данных которых ссылок нет (дашборд, отчёт по проектам), и когда страница открыта дольше срока жизни ссылки.
- **Вложения.** `GET /api/attachment/{id}/temporary-url?seconds=N` (по умолчанию час) возвращает подписанный адрес приложения на локальном диске и подписанную ссылку S3 на S3. `N` ограничен 7 днями (604800, предел подписи S3) на любом диске; большее значение даёт ошибку валидации. Ссылки выдаются только для проверенных (GOOD) вложений. Если `cattr:attachments:verify` обнаружит, что файл не совпадает со своим хешем, вложение получает статус BAD, а файл переносится в `quarantine/projects/<project>/<id>` на том же диске. Выданные раньше ссылки перестают работать: маршрут приложения проверяет статус, а подписанная ссылка S3 указывает на ключ, которого больше нет. Файл в карантине сохраняется для разбора и удаляется вместе с вложением или его проектом. Вложение со статусом BAD повторно не проверяется.
- **Отчёты.** Эндпоинты скачивания возвращают `/storage/reports/...` на локальном диске и подписанную ссылку на 10 минут на S3. Письмо с отчётом прикладывает файл, прочитанный с диска `reports`.

## Ротация и срок хранения скриншотов

`cattr:screenshots:rotate` и вкладка хранилища в настройках работают от свободного места на локальном диске. У объектного хранилища свободного места нет, поэтому при `FILESYSTEM_DISK=s3` ротация ничего не делает (`about/storage` возвращает `rotation_supported: false`). Срок хранения в этом случае задают правилами жизненного цикла бакета, например удалять объекты с префиксами `<AWS_ROOT>/screenshots/` (миниатюры лежат в `screenshots/thumbs/`) и `<AWS_ROOT>/reports/` через N дней. Префикс `attachments/` не трогайте. В отличие от локальной ротации, правило бакета не делает исключений для важных проектов, задач и пользователей с постоянными скриншотами.
